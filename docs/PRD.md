## 1. 这是什么产品

**一个打开网页就能用的通用 ChatBI 平台。**

业务同学在对话框里用一句人话提出业务问题，系统直接返回**结果表 + 一张图 + 一句业务解读**；口径不清楚时，它会先追问你「到底想看哪个指标、和什么比」，而不是猜一个答案给你；问的是它答不了的东西（竞品数据、订单明细、范围外的日期），它会明确拒绝并告诉你还能问什么——**永远不会给你一个编造的数字**。

问清楚、确认口径之后，这张结果可以**一键存成报表**。以后从报表入口打开就直接看到结果，不用再问一遍。这是本平台和「只能聊两句的问数玩具」最本质的区别：**对话是入口，不是全部**。

几个必须说清的定位：

| 维度 | 本平台是什么 | 本平台不是什么 |
| :--- | :--- | :--- |
| 产品形态 | 通用 ChatBI 平台，打开网页即用 | 某个行业或某个岗位的专用工具 |
| 能力范围 | 问数 → 澄清/拒答 → 对比分析 → 沉淀成报表 → 报表复用 | 完整商业化 BI 中台（自助看板搭建、归因分析、权限中台、计费） |
| 沉淀方式 | 把确认过的口径与展示配置存成报表，反复打开 | 从零拖拽搭建复杂仪表盘、报表编排与分发 |
| 行业适配 | 换行业只换指标字典与数据，产品功能不变 | 为电商单独做一套逻辑 |
| 本版形态 | 单用户、免登录、本地可部署可演示 | 多租户 SaaS、权限中台 |

> 一句话：**问得准、答得起、错了不编、好答案留得下。**

## 3. 平台面向谁

**所有要看数、要做分析的业务同学**——运营、商品、市场、管理层均可。

他们的共同特征是：

- 有明确的业务问题（卖得怎么样、哪个渠道拖后腿、为什么掉）
- 不会写 SQL，也不想为了看一个数去排队等数据同学
- 需要的是**口径可信**的答案，不是一堆原始数据

平台不锁定任何单一岗位，也不为某个特定角色定制流程。岗位之间的差异体现在**指标字典与数据**里，不体现在产品功能里。

## 5. 交互明细

> 只写本版要做的 F1~F8。每个功能单独一节，用固定维度写清：从哪进 → 怎么操作 → 系统怎么反馈 → 确认/取消 → 失败/空数据。F9~F11 的暂缓范围见 5.9。

### 5.1 对话问数（F1）

| 维度 | 设计 |
| :--- | :--- |
| **从哪进** | 打开网页即对话页（本版免登录）。布局：左侧栏（历史会话 / 报表）+ 中间对话流 + 底部输入框 |
| **怎么操作** | 输入自然语言问题 → 回车或点发送；或点击「提问参考」中的快捷卡，把问题填入输入框后再发送 |
| **过程怎么呈现** | 对话流先出用户问题气泡 → 加载态 → 结果卡片 |
| **结果卡片组成** | ① 结果表 ② 一张主图 ③ 一句业务解读 |
| **图表怎么选** | 类别对比用柱状图，时间序列用折线图；只做这两类，不做图表编辑器 |
| **解读怎么写** | 只给一句结论（涨了还是跌了、谁最高、差多少），不写长篇分析与投资建议 |
| **追问** | 同一会话内直接发问，系统沿用上文口径；追问生成新卡片，旧卡片保留 |
| **确认 / 取消** | 发送不可撤回，可直接重问；加载中可点「取消」中止本次请求 |
| **空数据** | 「该条件下暂无数据」+ 建议调整时间窗或维度 |
| **失败** | 请求失败显示错误态 + 重试按钮；图表渲染失败降级为「只有表 + 提示」；任何状态都不出现空白页 |

### 5.2 澄清（F2）

| 维度 | 设计 |
| :--- | :--- |
| **何时追问** | ① 缺指标（「表现怎么样」）② 缺对比基准（「增长了吗」）③ 缺时间窗（「最近卖得如何」「看一下转化率」）④ 要求因果解释（「为什么掉了」） |
| **追问长什么样** | 对话流中出现澄清卡片：一句追问 + 候选选项（点击即答）+ 自由输入框 |
| **示例** | 「想看哪个指标？」→ 候选：GMV / 转化率 / 客单价 / 退货率 |
| **系统怎么反馈** | 用户作答后立即据此重新解析问题并出结果；未作答前**不产生任何数字** |
| **确认 / 取消** | 可放弃该问题，会话保持可继续提问 |
| **失败** | 因果类问题不答因果，只提供 2~3 个可查的对照问法 |
| **铁律** | 澄清态输出中不得出现编造数字 |

### 5.3 拒答（F3）

| 维度 | 设计 |
| :--- | :--- |
| **何时拒** | ① 外部/竞品数据 ② 明细导出、行级数据 ③ 超出数据时间范围 ④ 写操作或改数请求 |
| **怎么拒** | 拒答卡片 = 一句拒绝原因 + 替代问法（可点击直接发起） |
| **示例** | 「没有竞品数据。可以改看：本品各渠道 GMV 对比」 |
| **系统怎么反馈** | 明确说明不可答的原因；给出可答的替代方向 |
| **确认 / 取消** | 点击替代问法即发起新查询；也可自行改写问题 |
| **失败** | 不返回空表假装答过，不给任何估算数字 |
| **铁律** | 拒答场景中不得输出任何编造数字 |

### 5.4 对比分析（F4）

| 维度 | 设计 |
| :--- | :--- |
| **什么问法** | 同比（和去年同期比）／环比（和上周、上月比）／双时段（大促期和大促前一周比） |
| **结果怎么呈现** | 对比表（本期值 / 对比期值 / 差值 / 变化率）+ 主图 + 一句解读（点明方向与幅度） |
| **口径怎么处理** | 两期口径必须一致；时段长度不等时按**日均**归一化，并在回答中写明 |
| **系统怎么反馈** | 解读只给「涨了还是跌了、幅度多少」，不展开原因分析 |
| **失败** | 对比期无数据时明确说明，不补假数；口径不一致时在结果中标注 |

### 5.5 一键存成报表（F5）

| 维度 | 设计 |
| :--- | :--- |
| **从哪进** | 每张问数结果卡片右上角「存为报表」 |
| **怎么操作** | 点击 → 弹出保存弹窗：报表名（默认取用户问题，可改）／图表类型（柱/线可切换） |
| **系统怎么反馈** | 保存成功提示 + 「去报表列表查看」引导入口 |
| **确认 / 取消** | 「保存」提交；「取消」关闭弹窗不留痕迹 |
| **同名怎么处理** | 提示已存在，二选一：改名 / 确认覆盖 |
| **存的是什么** | 问题口径 + 展示配置。再次打开按此直接出结果，无需重新提问 |
| **失败** | 提示失败原因并可重试，弹窗内已填内容保留 |

### 5.6 已存报表管理（F6）

| 维度 | 设计 |
| :--- | :--- |
| **从哪进** | 左侧栏「报表」 |
| **列表怎么显示** | 名称 + 来源问题 + 保存时间，按时间倒序；空列表显示空态与「去提问」引导 |
| **打开** | 点击进入报表视图：表 + 图 + 一句解读，**没有任何提问动作** |
| **改名** | 行内铅笔图标 → 直接编辑 → Enter 确认 / Esc 取消 |
| **删除** | 行尾删除图标 → 二次确认（提示不可恢复）→ 执行并从列表移除 |
| **失败** | 改名或删除失败给出提示，列表保持原状 |

### 5.7 对话记录（F7）

| 维度 | 设计 |
| :--- | :--- |
| **从哪进** | 左侧栏「历史会话」，按时间倒序；顶部搜索框可按标题过滤 |
| **怎么操作** | 点击任一会话 → 回看完整问答与当时结果；点「新对话」另起会话；hover 会话右侧删除图标可删除单条，标题右侧「清空」可一键删除全部（都需二次确认） |
| **系统怎么反馈** | 回看时结果保持当时形态，不重新计算；当前会话刷新页面后仍保留（本地记住会话指针） |
| **本版边界** | 本地单用户存储；跨端同步、跨用户共享随鉴权一并暂缓 |

### 5.8 一键部署（F8）

| 维度 | 设计 |
| :--- | :--- |
| **从哪进** | 仓库根目录的 README，按「启动」一节操作 |
| **怎么操作** | 三步：复制环境变量示例文件并填入模型密钥 → 执行 `docker compose up` → 浏览器打开本地端口 |
| **系统怎么反馈** | 控制台打印服务就绪信息与访问地址；首次启动自动建库并导入示例数据，或按 README 给的 seed 命令手动导入 |
| **首次可用性** | 起来后打开网页即可直接问一句并拿到结果，无需额外配置；示例问题 3 条写在 README 里 |
| **密钥怎么管** | 只走环境变量；仓库与镜像中不得出现真实密钥，示例文件只放占位符 |
| **失败怎么处理** | README 列出常见失败（模型接口不通、未导入示例数据、端口被占用、镜像拉取失败）与对应处理方式 |
| **确认 / 取消** | `docker compose down` 停止并清理；数据是否保留在 README 中写清 |
| **验收口径** | 在干净环境（无本地运行环境残留）成功跑通一次问数，才算部署完成 |

### 5.9 本版暂缓的功能（F9~F11）

以下三项不写交互明细，只说明暂缓范围与后续落点，避免以后重复讨论。

| # | 功能 | 暂缓到什么地步 | 后续落点 |
| :- | :--- | :--- | :--- |
| F9 | 口径可验证 | 结果区只给表 / 图 / 一句解读，不做查询条件复述，也不展示 SQL | 结果卡片增加复述行与 SQL 折叠块 |
| F10 | 效果评测 | 不做命令行评测 runner，靠人工按《测例》走查 | 抽出 5 条用例，加一条命令跑通并出对错 |
| F11 | 登录与鉴权 | 免登录、单用户打开即用；不做注册 / 登录 / 权限界面，左侧栏保留用户位 | 接入账号体系，对话与报表挂到账号下，再补多用户隔离与报表分享 |

> 三项都标注为「本版可暂缓」，不是「不需要」——平台最终要有，只是本版功能演示不做。

## 6. 平台原则：范围不清先问或拒，不许猜

这三条凌驾于所有功能之上，任何交互都不得违反：

1. **问题落在指标 / 维度字典之外** → 澄清或拒答，不得自行假定口径硬答。
2. **任何输出中的数字必须来自真实查询结果** → 查不到就明说，不做估算、不做推测。
3. **拿不准用户意图时** → 追问的成本永远低于答错的成本。

## 9. In / Out

### 9.1 In（本版平台能力）

对话问数与多轮追问；结果表 + 主图 + 一句解读；澄清与拒答；同比 / 环比 / 双时段对比；一键存成报表；报表列表 / 打开 / 改名 / 删除；对话记录（本地单用户）；Docker Compose 一键部署。

### 9.2 Out（不属于本产品方向）

- **商业化 BI 中台能力**：仪表盘从零搭建、报表编排与分发、权限中台、多租户与计费
- **分析深度**：归因、因果推断、趋势预测 / 推演（本产品只做数据对照，解读严格一句）
- **报告形态**：多句长解读、自动分析报告
- **模型工程**：生产级模型后训练、多模型自动选择编排（本版固定一条链路 + 三档模型变量 `MODEL_SMALL/STRONG/MID` 与独立 `EMBED_MODEL`，可填同一模型，换模型只改配置）
- **基础设施**：K8s 与生产级 CI/CD 全链路（Docker Compose 即满足 F8）
- **数据接入**：跨工具 / 跨源拉数、外部附件上传问答、无数据接入（L0 库结构）的裸链问答
- **数据出口**：明细数据导出、行级数据下钻
- **会话能力**：跨会话全文检索 / 搜索 / 导出
- **协作能力**：报表协作共享、订阅、定时推送
- **终端与交互**：移动端适配、流式输出

### 9.3 本版暂缓（平台需要，但演示版先不做）

- 口径可验证（查询条件复述、SQL 可查）
- 效果评测
- 登录与鉴权
- 多用户数据隔离 / 行列级 RBAC
- 报表分享

> 以上五项架构上预留用户字段与鉴权入口，本版不实现。

## 10. 怎样算成功

| 项 | 标准 |
| :--- | :--- |
| 问数链路 | 网页上问一句能出「表 + 图 + 一句解读」，并能继续追问；《测例》中数值题与对照口径一致 |
| 可信 | 该澄清的都追问了、该拒的都拒了，全程无编造数字 |
| 报表沉淀 | 问数结果可一键存为报表；从报表入口再次打开直接呈现，无需重新提问 |
| 报表管理 | 列表 / 打开 / 改名 / 删除按 §5.6 走通，含二次确认与空态 |
| 部署 | 干净环境 `compose up` 后打开网页即可完成一次问数 |

> 成功标准落在**平台能力**上，而不是「服务好了某一个场景」。
