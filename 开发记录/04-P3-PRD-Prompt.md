# 04·P3 写 PRD Prompt
调研已经做完了，接下来我觉得可以写 PRD 了。先别写技术方案，也别写代码。

这次不要写成「最小数闭环」那种很薄的需求。我要的是一份完整平台的开发 PRD：功能要写全，交互要写细，让人看了知道这个产品在网页上到底怎么用，后面开发能对照着做。登录鉴权这类流程可以标成本版演示先不做，但平台该有的能力不要因为 MVP 演示就把 PRD 写虚了。

先把这几份读完再动笔，别空写：
- `开发记录/01-实操方向-企业级ChatBI与电商落地.md`
- `docs/调研纪要.md`
- `docs/测例.md`

有个很重要的点，你写的时候必须按这个来，别顺着调研里的某个岗位把产品写成专用工具：
PRD 分两层写。上面一层才是产品本身：做一个通用的 ChatBI 平台。打开网页就能用；用对话问数，出表、出图、出一句解读；口径不清要问，不该答的要拒；问清楚并确认之后，结果要能沉淀成报表，以后直接打开看，不用再问一遍。换行业、换岗位，换的是业务含义，不是换产品。平台策略只由这一层决定。下面一层是首个验收切片：用电商大促复盘来证明问数能力落地。调研里的角色、场景、现成测例，都挂在这一层。可以在 PRD 里提，当作第一包问数演示和评测的例子，但不能反过来定义平台是给谁做的、只能干什么。对具体人群和细分场景的支持，留给后面应用技术方案去考虑。

调研纪要当背景看就行。里面那些数据怎么接、接哪张表、接哪种资源，现在都不要写进 PRD，那是后面技术方案才要考虑的。

我已经定了的结论，按这个写，别再问我，也别自己改主意：
1、产品定位按通用平台写，不要写成「大促复盘官专用系统」，也不要写成只能聊两句的问数玩具
2、不是完整商业化 BI 中台，但必须有平台体感。对话问数是入口，不是全部。至少要有：问数、出表出图出一句解读、澄清和拒答、对比（含同比环比）、口径和图表确认后一键存成报表、以后从报表入口打开就直接看、不用再问。你再补齐同类必要能力（比如对话记录、已存报表的列表/打开/改名/删除），但不要滑到「自己从零搭复杂仪表盘、报表编排分发、权限中台、计费」那种中台大而全
3、电商大促复盘只作为第一包问数验收场景提一下；docs/测例.md 仍用来验问数闭环，不要另起一套问数题。报表沉淀、报表管理这类平台功能，在 PRD 里单独写验收方式，不必硬塞进那 13 条测例
4、用户故事按平台能力写，主语不要锁死成某一个岗位。问数相关故事可以锚测例 id；报表等能力用你在 PRD 里写的交互来验收
5、解读就一句业务解读，别写成带投建议的长分析
6、澄清、拒答是平台通用规则，要写清楚、写到能执行
7、登录、鉴权、多用户权限：PRD 里要写到这是平台该有的，并标明「本版功能演示可以先不做」。不要假装平台永远不需要，也不要本版就做成完整权限中台
8、每个核心功能都必须写交互明细，不能只丢一句能力名称。至少写清：从哪进、用户怎么操作、系统怎么反馈、确认/取消怎么办、失败或空数据怎么办

只产出一个文件：`docs/PRD.md`。别新建别的文档，别改调研和测例，别碰代码。

内容上请覆盖这些，章节你可以自己排，但别漏：
1、一句话说明这是什么产品。强调它是能打开网页实际用的通用ChatBI平台：既能对话问数，也能把确认过的结果沉淀成报表反复使用
2、平台面向谁：要看数、要做分析的业务同学即可，不要把某一个调研角色写成唯一用户
3、功能总览：用一张表列出平台功能。每项标「本版演示要有」还是「本版演示可暂缓」。问数、出结果、澄清拒答、一键存报表、再打开报表，标成演示要有；鉴权这类标成可暂缓
4、分功能写交互明细（这是重点，写虚了就不合格）。至少单独写清这几块：
- 对话问数：怎么提问、怎么看到对话过程、结果区怎么出表/图/一句解读
- 澄清：什么时候追问、追问长什么样、用户确认前不出数
- 拒答：什么时候拒、怎么说明原因、不许编数
- 对比：同比、环比、前后时段怎么问、结果怎么呈现
- 一键成报表：用户确认口径和图表之后，怎么一键保存；保存后从哪入口能找到；再次打开就是看报表，不用重新问一遍
- 已存报表：列表、打开、改名、删除这些基础管理怎么操作
- 对话记录：能不能看到自己问过什么（有就写交互，没有也要在 Out 或暂缓里说清，别瞒过去）
5、单独一小节写「第一包验收场景」：电商大促复盘，只用来演示和评测问数，不构成平台边界
6、用户故事 5～8 条，覆盖问数和报表沉淀，不要只写问数
7、In / Out 写清楚。In 是完整平台该有的能力（含报表沉淀）；Out 是完整 BI 中台那类重能力，以及本版演示明确暂缓的（如鉴权）。调研里的场景细节不要膨胀成

8、范围不清先问或拒、不许猜
9、问数演示和评测测仍引用 docs/测例.md；平台功能（存报表、再打开报表）单独验收
10、怎样算成功：既要网页上问一句能出结果、该拒能拒，也要能把确认过的结果存成报表并再次打开。成功标准落在平台能力上，不要写成「服务好大促复盘官」
