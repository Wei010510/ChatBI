# 01 · 实操方向：企业级 ChatBI × 电商落地

> 选方向是 VibeCoding 的第一步：方向不对，后面文档和 Agent 都会跑偏。

---

## 实操方向

**企业级 ChatBI 平台工具 + 电商行业落地**

最后要交出来的不是一段能跑的逻辑，而是一个**平台型工具**：用户打开 Web 页面，就能真正问数、看表、看图、看解读。

| 层级     | 含义                     | 例子                               |
| :------- | :----------------------- | :--------------------------------- |
| 交付形态 | 平台型工具，Web 可实际体验 | 打开网页 → 对话问数 → 看到表/图/解读 |
| 产品能力 | ChatBI：对话式取数/分析    | 自然语言问数 → 表/图/解读            |
| 行业载体 | 电商                     | GMV、转化、退货、渠道、大促        |

---

## 为什么选 ChatBI

### 1. 产品化成熟、可参考性强

BI 是成熟产品化方案，也是最早一批成功应用大模型的典型场景；竞品与公开方案多，适合在成熟品类里练「用 AICoding 做出来」。

### 2. 智能体技术能长在主链路上

从「单次 NL2SQL」走向：澄清口径 → 查数 → 校验 → 解读 → 可视化 → 评测回归。

正好体现：工具调用、多步编排、状态交接、失败重试、效果评测。

### 3. 企业级约束天然在场

指标口径、权限边界、拒答与澄清、结果可追溯 → 必须做 Harness（PRD / SDD / spec）和评测，而不只是 Prompt。

### 4. 闭环清晰、适合成片验收

打开网页，一句话进，表/图/解读出 → 问得通、答得对、错了能拒。不是只在命令行里跑通。

## 为什么选电商落地

| #   | 理由               | 要点                                                       |
| :-- | :----------------- | :--------------------------------------------------------- |
| 1   | 老牌行业，指标好懂 | GMV、转化率、客单价、退货率、渠道、大促                    |
| 2   | 复杂度刚好够用     | 能接运营资源（活动/券等），又不必一上来就上重合规叙事        |
| 3   | 故事好串全片       | 统一「大促复盘官」视角，测例同时服务演示与评测               |
| 4   | 方法可迁移         | ChatBI 平台是载体，电商是皮肤；换行业时换业务字典即可        |

## 做什么 / 不做什么

| 做                                             | 不做                               |
| :--------------------------------------------- | :--------------------------------- |
| 能在 Web 页面上打开、实际问、实际看结果的平台型工具 | 只在命令行/笔记本里跑通的演示脚本    |
| 可问数、可解读、可拒答、可评测、可部署的最小企业级闭环 | 完整商业化 BI 中台                   |
| 用 VibeCoding 从 0 做到可演示、可上手体验        | 从零讲 BI 理论                     |
