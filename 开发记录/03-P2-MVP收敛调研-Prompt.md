`docs/调研纪要.md` **结构**

### 1. 垂直故事
- 选定 1 个主故事（默认倾向：电商「大促复盘官」/运营分析师），可另给 1 个备选
- 写清：角色、何时用、要支持什么决策、一句话产品定位（最小可演示闭环，非完整商业中台）

### 2. 定向调研（深在决策点，不写行业长文）
至少覆盖 2～3 个 ChatBI / 对话式分析类参考（产品或公开方案均可）。对每个参考写：
- 名称与类型（产品 / 开源 / 方案文章）
- 交互要点 3～5 条（提问、澄清、结果呈现、追问等）
- 能力边界要点 2～4 条（它强调做什么、明确不碰什么）
- 可借鉴到本 MVP 的点 2～3 条
- 信息不确定处标注「待核实」

禁止：融资/市占率综述、大而全功能矩阵、API/DDL/Agent Prompt 全文。
另用一小节写：对本项目的启示（综合竞品后，我们更该强调什么、裁掉什么）。

### 3. MVP In / Out（必须在调研之后写，体现「参考后的裁剪」）
#### In（可微调措辞，勿扩大成大系统；写明「因调研而保留/采纳」的依据一句即可）：
- 自然语言问数（限定指标/维度字典内）
- 结果表 + 简单图表 + 一句业务解读
- 澄清 / 拒答（口径歧义、超范围、无数据）
- 至少 1 个运营资源接入示意（活动日历 / 券 / 渠道维，给出推荐项 + 理由）
- 少量效果评测 case
- Docker Compose 可部署

#### Out：
- 完整权限中台 / 多租户计费
- 复杂归因 / 因果推断
- 生产级模型后训练全链路
- K8s / 生产级 CI/CD 全链路
- 其他你根据调研认为应明确裁掉的项（列出）

### 4. 待我拍板清单
3～7 条勾选选项（故事备选、运营资源选哪个、测例增删等）。仅限产品与范围决策，不要写技术实现选型。

## docs/测例.md 结构
- 文首 3～5 行：测例同时服务演示与评测；PRD/评测不得另起一套题；测例均落在上文 In 内。
- 12～15 条测例，全部服务已选垂直故事。
- 每条包含： id / 用户问题 / 考察点（取数|对比|解读|澄清|拒答|运营资源） / 期望结果类型（表/图/解读/追问） / 对应 In 项
- 覆盖：渠道 GMV/转化、类目退货、大促前后对比、AOV、至少 1 条澄清、至少 1 条拒答、至少 1 条挂上推荐运营资源
- 用户问题要具体可测，禁止「分析一下经营情况」这类空泛句
- 若某条可能越出Out，删除或改进

## 完成标准
- 顺序正确：故事 → 调研 → MVP IN/OUT → 测例
